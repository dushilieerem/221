## 2. 项目背景

ResearchEngine 是独立的量化投研计算服务。SVQuant 中的 WebApp 通过 HTTP 调用它；调用方不导入本仓库的 Python 包，也不读取本仓库的本地资产。

项目需要统一承载因子和策略研究请求、访问有版本标识的行情数据、执行回测并返回结构化结果。研究服务还提供因子/策略目录与行情查询。

当前基线解决以下工程问题：

1. 将计算和 HTTP 适配放在独立服务中，明确与 WebApp、MarketData 和本地研究资产的边界。
2. 让回测输入、行情发布版本和执行结果可关联，减少数据版本变化带来的不可复现问题。
3. 为单次回测和研究客户端提供可查询的任务状态及稳定接口。

---

## 3. 项目目标

### 3.1 业务目标

- 通过统一研究服务支持因子分析、策略验证及市场数据查询。
- 让 WebApp、CLI、SDK 或其他受信任客户端复用同一套研究计算能力。
- 为后续研究流程扩展保留清楚的服务、数据和任务边界。

### 3.2 用户目标

- 研究员能够提交因子或策略回测，并读取指标、曲线和诊断信息。
- 调用方能够查询因子库、策略库、股票、指数和已发布行情。

### 3.3 系统目标

- 使用一个 `/api` HTTP 契约提供研究服务。
- 启动时加载并校验本地 YAML 配置和外部行情清单。
- 单次因子回测和策略回测分别使用明确的任务与持久化边界。
- 以 Python 3.11 为当前运行环境，保持核心计算及数据访问可测试。

| 角色 | 说明 | 主要操作 |
|---|---|---|
| 研究员 / 策略开发者 | 通过受信任客户端使用研究能力 | 查询资产和行情、提交回测、分析结果 |

当前 API 未实现身份认证、角色授权和租户隔离；上表是使用职责，不代表系统内置的权限角色。

## 5. 功能范围

### 5.1 当前功能

- 因子回测与因子分析，包含异步任务提交、查询和取消。
- 策略回测，支持当前实现的向量化和日频事件策略能力；具体能力由策略契约约束。
- 因子库、因子条目、策略目录和已发布市场数据查询。
- 全部 AI 功能（因子/策略生成、回测解读、策略转写、帖子摘要）已于 2026-11-05 移交 SVQuant。
- 外部行情数据清单校验、字段读取缓存和回测结果序列化。

### 5.2 当前不包含

- 用户、租户、团队、权限、计费和审计后台。
- Web 前端页面、实时行情接入、券商连接、实盘交易或订单路由。
- 跨实例共享的任务队列、任务状态和并发协调；当前部署按单实例、单 Worker 使用。
- 面向不受信任 Python 代码的进程或容器沙箱。
- AI 自动改写策略、自动执行生成代码或自动迭代调参。

## 6. 功能需求

### 6.1 配置与行情发布校验

#### 功能说明

服务从仓库根目录 `config.yaml` 读取运行配置，并只读访问配置指定的 MarketData 发布目录。

#### 使用场景

当运维人员启动服务时，系统需要确认配置、清单和行情版本匹配后再开放接口。

#### 输入与处理规则

- 输入包括服务端口、并发上限、数据目录、`data_manifest.yaml`、期望数据版本和资产路径。
- 可配置清单 SHA-256 校验；启用逐资产校验时，会校验清单声明的文件哈希。
- 缺少正式配置、数据文件或出现版本/哈希不一致时，启动失败并记录原因。

#### 输出、异常与验收

- 成功时应用装载行情 Provider 并启动任务管理器。
- 异常时应用不进入可用状态；`GET /api/health` 只用于服务启动后的健康检查。
- [ ] 使用正确配置和数据发布可完成启动。
- [ ] 配置或清单校验失败时启动日志包含可定位的错误信息。

### 6.2 因子回测

#### 功能说明

调用方提交因子代码或已登记因子及回测规格，系统计算因子、构建组合并返回指标和分析结果。

#### 输入与处理规则

- 输入由 `FactorBacktestRequest` 定义，包含因子来源、股票池、日期区间和回测参数。
- 系统规范化请求和数据身份，通过 `ExperimentManager` 有界排队，并由 `BacktestEngine` 编排数据、因子、组合和指标服务。
- `POST /api/backtest/factor` 返回 `202 Accepted` 和 `run_id`；调用方通过任务查询端点读取状态与结果。

#### 输出、异常与验收

- 成功任务返回结构化指标、因子分析、回测元信息及请求的结果数据。
- 队列已满返回 `429`；未知任务返回 `404`；参数、数据或计算错误由响应/任务状态表达。
- [ ] 可提交并轮询因子任务，成功时读取结果。
- [ ] 可取消尚未运行的任务；运行中取消以取消请求表示，不强杀 Python 线程。

### 6.3 策略回测

#### 功能说明

调用方提交向量化目标权重或当前支持的事件策略定义，系统按相应执行器回测。

#### 输入与处理规则

- 请求和策略能力由 `StrategyBacktestRequest` 及策略执行契约定义。
- 工作由 `ExperimentManager` 调度；HTTP 路由等待结果后同步返回。
- 策略必须符合对应 execution mode 的可用能力；不支持的数据频率或交易能力应显式报错。

#### 输出、异常与验收

- 返回结构化策略结果、净值、指标、持仓/成交信息（依执行模式和请求而定）。
- 队列满返回 `429`；管理器关闭返回 `503`；输入和能力错误按 API 错误契约返回。
- [ ] 支持的策略请求可返回结果。
- [ ] 不支持的策略能力不会被静默降级为另一种执行语义。

### 6.4 目录和行情查询

#### 功能说明

调用方查询内置因子库、因子、策略、股票、指数、指数成分和单标的日线。

#### 输入与输出

- 输入为路径参数和可选的日线 `start` / `end`。
- 输出为对应 Pydantic 响应模型；行情只来自当前已装载的数据发布。
- 未知资产或不可用行情返回明确的 HTTP 错误。

#### 验收标准

- [ ] 所有目录查询与数据查询路径均能返回定义的响应模型。
- [ ] 查询不写入或修改 MarketData 源文件。

### 6.6 AI 辅助（已移交 SVQuant）

AI 因子生成、策略生成、回测解读、策略转写和社区帖子摘要已于 2026-11-05 移交 SVQuant，RE 侧代码、路由与 `ai.*` 配置已删除；历史契约见 [归档说明](../归档/已移交-SVQuant/README.md)。

## 7. 业务规则

- 每次研究请求绑定明确的请求参数和当前 MarketData 发布版本；数据清单版本必须与部署配置一致。
- 因子计算可能需要收益确认区间之前的历史数据预热，最终统计范围仍按请求定义；详见 ADR-018。
- `listed_status` 与 `up_and_down_status` 表示不同状态信息。`up_and_down_status` 为 NA 只表示该字段当日无记录，不能据此判断股票退市。
- 回测任务状态和队列保存在当前进程内；重启后不可作为可靠历史任务继续查询。
- 用户提交的 Python 代码只能来自受信任调用方；当前运行时不提供安全沙箱。

## 8. 非功能需求

### 性能

服务未在仓库中声明 QPS、P95 或最大数据规模 SLA。回测并发和排队容量通过 `runtime.max_workers` 与 `runtime.max_queue_size` 配置，默认分别为 2 和 8。

### 稳定性

- 启动时校验配置和行情发布；校验失败时拒绝启动。
- `ExperimentManager` 使用有界队列，容量耗尽时立即拒绝请求。

### 安全

- 当前没有 API 身份认证、授权、租户隔离或用户代码沙箱。
- `config.yaml` 被 Git 忽略；真实 API Key 不得写入模板、提交记录或日志。
- 部署应限制网络访问，尤其是可提交 Python 源码的回测接口。

### 数据规模与并发

- 行情规模由外部 MarketData 发布决定；服务启动时不会将所有行情读入内存。
- 当前正式入口固定 `uvicorn workers=1`。增加 Worker 或实例前，需要先将任务和缓存状态迁移到共享协调设施。

### 可用性

- FastAPI 自动提供 OpenAPI 文档；默认地址为 `/docs`。
- 健康检查端点为 `GET /api/health`。

## 10. 风险与待确认项

### 风险

- [ ] API 缺少认证与授权；不应直接暴露给不受信任网络。
- [ ] 用户 Python 代码在服务进程内执行，缺少 CPU、内存和系统调用隔离。
- [ ] 任务状态是进程内状态，不支持多实例共享或服务重启恢复。
- [ ] 仓库未声明性能目标和外部行情覆盖率 SLA。

### 待确认

- [ ] 若服务要面向公网或多租户，先定义身份、权限、限流与审计契约。
- [ ] 若需要横向扩展，先设计共享任务队列、持久状态和独立 Worker。
- [ ] 由产品/运维补充服务级可用性、延迟和数据保留目标。
