# ResearchEngine 使用说明

## 1. 系统简介

ResearchEngine 提供量化研究 HTTP API，用于因子分析、策略回测、已发布行情查询和因子批量回测。它是服务端组件，没有独立 Web UI；通常由 SVQuant WebApp 或受信任的研究客户端调用。

适用用户：量化研究员、策略开发人员、接入 ResearchEngine 的 WebApp/CLI/SDK 调用方。

---

## 2. 连接服务

确认服务已部署并通过健康检查：

```bash
curl -fsS http://127.0.0.1:9527/api/health
```

默认 API 文档地址：`http://127.0.0.1:9527/docs`。主机和端口可由部署配置更改。

---

## 3. 功能导航

| 功能 | 用途 |
|---|---|
| 因子库和因子列表 | 获取可回测的内置因子和目录元数据 |
| 策略列表 | 获取随服务发布的策略资产 |
| 行情查询 | 股票、指数、指数成分和单标的日线 |
| 因子回测 | 异步提交、轮询状态/结果、请求取消 |
| 策略回测 | 提交向量化或当前支持的事件策略并等待结果 |
| 因子批量回测 | 按批次运行因子、查询批次和历史指标 |
| AI 辅助 | 生成因子/策略草稿或解释回测结果 |

详细路径和 DTO 见[API 设计](../接口设计/API设计.md)。

## 4. 常用操作

### 4.1 查询资产和行情

```text
GET /api/factor-libraries
GET /api/factors/{library_name}
GET /api/strategies
GET /api/market-data/symbols
GET /api/market-data/indices
GET /api/market-data/daily/{symbol}?start=YYYY-MM-DD&end=YYYY-MM-DD
```

指数成分使用 `GET /api/market-data/indices/{code}/constituents`。完整参数和响应示例见 API 设计页中的详细接口链接。

数据版本使用 `GET /api/data/status` 查询，返回当前 `data_version`、`release_id` 和 `data_dir`。服务自动跟随行情发布更新（发布完成后约 1~2 分钟生效，无需重启）；需要立即生效时可调用 `POST /api/data/reload`。

### 4.2 提交因子回测

1. 按[因子回测 API](../功能包/FEAT-002-研究引擎/06-研究接口文档/backtest-factor.md) 组装请求。
2. 调用 `POST /api/backtest/factor`。
3. 保存 `run_id` 和返回的 `poll_url`。
4. 按响应建议间隔调用 `GET /api/backtest/factor/{run_id}`，直到任务终止。
5. 如需请求取消，调用 `DELETE /api/backtest/factor/{run_id}`。运行中的 Python 线程不会被强制终止。

任务状态和结果只在当前服务进程内短期保留；需要长期保存时，调用方应保存收到的结果。

### 4.3 提交策略回测

调用 `POST /api/backtest/strategy`。该接口等待回测结束后返回结果；策略输入应符合对应模式支持的行情频率、订单和持仓能力。

编写规范：

- [向量化策略编写规范](因子与策略指南/02-vectorized-strategy-writing.md)
- [事件策略编写规范](因子与策略指南/03-event-strategy-writing.md)
- [策略部因子与策略编写手册](因子与策略指南/00-策略部因子与策略编写手册.md)

### 4.4 批量回测与 AI 生成（已移交 SVQuant）

因子批量回测（含 CLI 与批次历史）和 AI 因子生成、策略生成、回测解读、策略转写已于 2026-11-05 移交 SVQuant，RE 不再提供对应路由和 CLI。历史文档见 [归档说明](../归档/已移交-SVQuant/README.md)。

### 4.5 帖子摘要兜底

部署人员先在本地 `config.yaml` 配置 `ai.base_url`、`ai.api_key` 和 `ai.model`，`POST /api/ai/post-summaries` 仍由 RE 提供，直到 SVQuant 移除 RE fallback。密钥不应随请求传递，也不要放入代码或日志。

### 4.6 与聚宽回测对账

用同一策略在聚宽与 SVQuant 事件引擎各跑一次，按参数、日历、成交、持仓、净值、指标逐层比对：

```bash
# 页面导出（收益概述/交易详情/持仓&收益）或 get_backtest() 导出
python -m app.cli.joinquant_parity import-golden --case fixed_basket_hold --from DIR
python -m app.cli.joinquant_parity validate --case fixed_basket_hold
python -m app.cli.joinquant_parity run --case fixed_basket_hold
python -m app.cli.joinquant_parity compare --case fixed_basket_hold
```

聚宽导出文件只在本机 `tests/parity/cases/<case>/expected/` 使用，不提交、不分发。详见 [FEAT-034](../功能包/FEAT-034-聚宽对账基线/README.md)。

## 5. 数据字段和状态说明

- `up_and_down_status` 表示交易状态信息（例如涨跌停、停牌）；`listed_status` 表示上市生命周期状态。
- `up_and_down_status` 为 NA 只说明该字段该日没有可用记录，不等价于退市；面板会包含上市日前的统一日期行，字段覆盖也可能晚于上市状态记录。
- 字段可用区间、缺失规则和来源以本次 MarketData release 的数据清单与字段说明为准。
- 不要用最新静态值回填历史字段，也不要把缺失值自动当成零、停牌或退市。
- 查询和回测只读使用已发布行情；回测结果应记录使用的数据版本，即 `release_id` 与 `data_version`（`GET /api/data/status`）。

## 6. 错误处理

| 现象 | 建议处理 |
|---|---|
| `422` | 根据响应指出的字段检查请求参数和 JSON 类型 |
| `404` | 检查库名、标的代码、run ID 或 batch ID |
| `429` | 队列已满，按 `Retry-After` 等待后重试 |
| `503` | 检查服务是否关闭、行情 Provider 是否可用，并查看部署日志 |
| 因子任务长时间未完成 | 轮询任务状态并联系运维查看 Worker/数据读取日志 |
| 任务 ID 重启后不存在 | 任务状态是进程内临时状态；长期结果应使用调用方持久化或批量历史 |
| AI 请求错误 | 检查 Provider 配置、密钥、网络和外部配额 |

---

## 7. 权限和使用限制

- 当前 API 不要求 Token，但这不代表接口公开安全；仅通过受控网络访问。
- 因子和策略 Python 代码在服务当前进程中执行，不要提交不受信任代码。
- 当前正式服务按单 Worker、单实例使用；不要在未迁移任务状态前直接水平扩容。
- 本服务提供研究模拟，不是交易执行系统；回测成交规则和数据时点需单独核对。

项目未在仓库中登记维护团队或支持邮箱。遇到运行故障时，请向 ResearchEngine 部署维护人员提供请求时间、任务 ID、数据版本及脱敏后的错误日志；不要附带 API Key 或其他密钥。
