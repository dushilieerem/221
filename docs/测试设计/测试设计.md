# ResearchEngine 测试设计

## 1. 测试目标

验证：

1. 配置、数据模型和请求 Schema 能拒绝无效输入。
2. 数据 Provider、因子/策略执行及指标计算符合已定义契约。
3. API 的路径、状态码、响应结构和任务生命周期符合约定。
4. 并发、缓存、批量持久化和 AI 适配在边界条件下保持可解释行为。

本页是仓库测试范围说明，不表示本次文档变更已运行测试或测试当前全绿。

---

## 2. 测试范围

### 包含

- 单元测试：配置、Provider、字段缓存、引擎、指标、模型、目录和策略。
- 集成测试：因子回测管线、批量任务队列、批次 SQLite、运行时和 API 调用。
- API 契约测试：请求/响应 schema、路由、状态码、异步任务行为。
- AI 接口测试：模型 Provider 失败、结构解析、白名单校验和输出契约。

### 不包含

- 对实时行情、券商和实盘交易的端到端验证；本仓库不提供这些系统。
- 对所有外部 MarketData 发布版本的穷举字段覆盖测试。
- 自动证明用户自定义 Python 代码安全；当前实现没有安全沙箱。
- 未提供真实压测环境时的生产 QPS、P95 和容量 SLA 验证。

## 4. 测试环境

- Python：3.11，环境名 `researchengine`
- 依赖：`pip install -e ".[all,dev]"`
- 测试框架：pytest；API 测试使用 HTTPX/TestClient 相关依赖
- 行情：优先使用仓库内小型 fixture 或测试替身；不要在单元测试中依赖生产数据目录
- SQLite：使用每项测试隔离的临时数据库路径
- AI：使用 mock Provider/响应；常规测试不应依赖真实密钥或外部模型可用性

## 5. 核心测试场景

| 场景 | 主要测试位置 | 预期结果 |
|---|---|---|
| 配置缺失、非法值、路径解析、AI 配置 | `tests/test_configuration.py` | 配置校验失败给出字段级错误；有效设置解析正确 |
| API 路由和请求/响应契约 | `tests/test_api.py`、`tests/api/test_v2_contract.py` | 路径、状态码、结构及错误语义稳定 |
| 因子目录和 SQLite 因子加载 | `tests/test_factor_catalog.py`、`tests/test_sqlite_factor_loader.py`、`tests/quantcore/test_sqlite_loader.py` 如适用 | 库、因子、代码和元数据读取正确 |
| 因子计算及回测主链 | `tests/test_research.py`、`tests/test_factor_backtest_async.py`、`tests/test_factor_backtest_engines.py` | 规格、面板、组合、指标和结果可衔接 |
| Manager 状态、并发、取消和队列满 | `tests/test_experiment_manager.py`、`tests/services/test_experiment_contract.py` | 状态转换正确；容量上限有效；取消语义不夸大 |
| 批量回测幂等、排队和持久化 | `tests/test_factor_batch.py`、`tests/services/test_factor_backtest_batch_queue.py`、`tests/services/test_factor_backtest_batch_tasks.py`、`tests/repositories/test_factor_backtest_repository.py` | 批次/单因子状态、指标和查询一致 |
| 字段缓存、MarketData 模型和 Provider | `tests/quantcore/test_field_cache.py`、`tests/services/test_market_data_models.py` 等 | 缓存及数据结构符合输入约束 |
| AI 因子/策略/回测解读 | `tests/test_ai_factor_api.py`、`tests/test_ai_backtest_interpretation.py` | Provider 错误、输出校验和降级响应符合契约 |
| 策略库和策略执行 | `tests/test_strategy_library.py`、`tests/quantcore/test_event_backtest.py` 及各迁移用例 | 目录解析和策略执行语义稳定 |
| 聚宽对账基线与分层比对 | `tests/parity/`（合成用例始终运行；真实金标缺失时端到端用例 skip） | 符号映射、金标 schema、L0–L5 分歧定位和退出码符合契约 |

实际测试文件清单以 `rg --files tests` 为准；表中列出的路径用于说明主要覆盖区域。

## 6. 边界测试

- 缺少或错误的配置、清单、数据版本和资产路径。
- 空数据、字段全 NA、单一股票/日期、上市前数据和不完整行情覆盖。
- 因子输入全缺失、因子值常数、分组样本过少、远期收益区间不足。
- `max_workers` 最小值、`max_queue_size=0`、队列满和 Manager 关闭。
- 重复任务键、重复批次键、取消排队任务、取消运行中任务、终态任务过期。
- SQLite 重复主键、外键错误、WAL 并发写和 schema 版本不匹配。
- AI 输出不是 JSON、字段缺失、函数/表达式超出白名单、密钥缺失和 Provider 超时。

---

## 7. 异常测试

| 异常 | 预期行为 |
|---|---|
| 数据清单 SHA-256 不匹配 | 应用启动失败，日志提供 expected/actual 摘要 |
| MarketData 目录或目标文件缺失 | 启动失败或相关请求返回明确数据错误 |
| Provider 不可用 | 当前请求失败；不应伪造有效行情或指标 |
| 回测队列满 | 返回 `429` 和可重试提示 |
| AI 外部服务超时 | 返回 AI 接口错误/降级响应；普通回测不受影响 |
| 批量 SQLite schema 版本错误 | 初始化拒绝不兼容数据库 |

## 8. 性能测试

性能目标当前未定义。建立压测前应先确定数据 release、股票数量、字段数、因子复杂度和并发模型。

| 指标 | 当前目标 |
|---|---|
| QPS | 未定义 |
| P95 响应时间 | 未定义 |
| CPU | 未定义 |
| 内存 | 未定义 |
| 回测并发/排队 | 配置默认 2 / 8，非服务 SLA |

建议分别测量冷字段读取、热缓存、因子计算、完整回测、批量队列和 AI Provider 延迟。

---

## 9. 回归测试

每次修改以下边界时优先覆盖对应测试：

- `app/schemas/backtest.py` 或路由：API 契约测试。
- `app/config.py` / `app/main.py`：配置、runtime 和启动校验测试。
- `app/services/backtest` 或 `app/services/{data,factor,portfolio,metric}`：因子回测/指标回归。
- `app/services/experiment`：任务队列、去重、取消和 shutdown。
- `app/services/factor_backtest_batch` / `app/database/factor_backtest_store.py`：批量状态和数据库查询。
- `app/api/ai_*` / `app/api/llm_provider.py`：AI mock API 测试。

## 10. 验收标准

- [ ] 与改动相关的单元、集成和 API 契约测试通过。
- [ ] 新增/修改公开 API 时，响应 schema 与详细 API 文档同步。
- [ ] 修改数据库 schema 时，版本、迁移/重建策略、关系和测试同步。
- [ ] 修改数据字段处理时，缺失值、点时性和状态字段语义有边界测试。
- [ ] 生产发布性能目标经目标数据环境验证后记录，不把本机结果冒充 SLA。

本机运行命令：

```bash
conda activate researchengine
pytest -q
```
