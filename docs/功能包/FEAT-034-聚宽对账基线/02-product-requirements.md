# 聚宽对账基线：产品需求

## 1. 背景

研究团队反馈"自研回测问题很多"，但无法量化问题来源。聚宽是团队熟悉的对标平台，回测结果与聚宽不一致会直接影响策略迁移与结论可信度。

已知差异来源至少四类：

1. **数据**：复权基准、停牌/涨跌停/ST 标记、退市、指数成分、财务公告日；
2. **参数**：聚宽默认滑点 `PriceRelatedSlippage(0.00246)`、默认 `use_real_price=False`、默认费率与最低佣金；
3. **撮合**：成交时点、整手、T+1、涨跌停拦截；
4. **账户**：分红送转、现金拖累。

在没有金标基线的条件下，无法区分"引擎错"与"口径不同"。本 Feature 只建立度量工具，不在本期修改引擎。

## 2. 用户故事

| 编号 | 用户故事 |
|---|---|
| US-1 | 研究员可以把一段聚宽策略与对应 SVQuant 策略放进同一个用例，一键比较两侧曲线。 |
| US-2 | 研究员能看到"第一个不一致发生在哪一天、哪只股票、哪个字段"，而不是只看到总收益差。 |
| US-3 | 研究员能区分"预期内的口径差异"（复权、整手现金拖累）与"真实分歧"（成交遗漏、持仓错位）。 |
| US-4 | 开发可以在 CI 中运行比对逻辑的单元测试，不需要聚宽金标或生产行情。 |
| US-5 | 合规要求：聚宽导出文件仅本地使用，不进入版本库。 |

## 3. 范围

### 包含

- 日频、A 股、事件驱动策略。
- 固定篮子持有用例（首个）。
- 聚宽 `get_backtest` 导出结果的规范化。
- 分层比对与报告。
- CLI 与 pytest 两种入口。

### 不包含

- 聚宽策略代码自动转写（见 FEAT-033）。
- 因子回测与向量化策略的撮合级对账（两者不是账户模型，没有对齐对象）。
- 分钟级、ETF、期货、融资融券。
- 自动把差异归类为"可接受"；只有用例显式声明才降级。

## 4. 验收标准

| 编号 | 验收标准 |
|---|---|
| AC-1 | `case.yaml` 声明两侧初始资金、佣金、最低佣金、印花税、滑点、基准，未填必填项时 `validate` 返回 2。 |
| AC-2 | 聚宽导出缺少 `daily.csv` 或 `positions.csv` 时返回 2，并指出缺失文件。 |
| AC-3 | 缺少必需列时返回 2，错误信息包含文件名、缺失列与实际列。 |
| AC-4 | 两侧完全一致时报告状态为 `pass`，退出码 0。 |
| AC-5 | 任一日收益或累计收益超出容差时退出码 1，报告给出首个分歧日期。 |
| AC-6 | 成交事件（日期/标的/方向）或每日持仓集合不一致时，即使 `price_basis=hfq` 也判失败。 |
| AC-7 | 复权基准不同导致的股数、价格、现金差异标记为参考差异，不影响退出码。 |
| AC-8 | 金标目录不存在时 `pytest tests/parity` 跳过端到端用例并说明原因，其余用例通过。 |

## 5. 合规与边界

- 只消费用户本地、合法导出的回测明细；不联网、不保存凭据。
- 金标目录 `tests/parity/cases/*/expected/` 已加入 `.gitignore`。
- 报告中的 provenance 记录回测 ID、导出时间、数据 release 与源码哈希，便于复现。
