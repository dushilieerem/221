# 13 个公司策略与聚宽对齐：路线与状态

> 策略源码：`SVQuant/docs/数据设计/聚宽策略源码/公司策略`（只读快照，8,056 行）。
> 数据缺口：`SVQuant/docs/数据设计/iFinD数据缺口-13策略.md`（v2）。
> 已确认路线：**聚宽兼容层**；首批试点 **MA趋势跟踪 + 成长多因子**；财务数据**免费源优先**。

## 1. 为什么是兼容层

13 个策略共 8,056 行，且大量依赖聚宽专属 API（`get_fundamentals`、`get_current_data`、`get_price(fq='pre')`、`g`、`run_daily(time=...)`）。手写重写会把翻译误差混入对账，无法区分"引擎不一致"和"翻译错了"。

兼容层把原始聚宽源码当作唯一事实来源：

```text
聚宽策略源码（不改逻辑）
        ↓
polyfill：g / run_daily / get_price / get_current_data / get_fundamentals / 下单函数
        ↓
SVQuant 事件时钟 + DataEngine + 账户账本
```

差异只可能来自**数据**或**引擎**，这正是对账要定位的。

## 2. 已确认的聚宽日频语义（2026-10-31 探针）

探针：`tests/parity/probes/jq_daily_semantics.py`，`context.run_params.frequency == "day"`。

| 时点 | `last_price` | 下单结果 |
|---|---|---|
| 09:00 | 昨收 | — |
| open / 09:30 | 当日开盘 | 按开盘价成交（此前后续用例已证明） |
| 09:31 | 盘中价（可≠开盘） | **按 09:31 的 `last_price` 成交** |
| 14:50 | 盘中价 | **按 14:50 的 `last_price` 成交** |
| 15:10 | 当日收盘 | 订单状态 `new`、`filled=0`，现金被冻结，当日不成交 |

另外两点：

- `day_open` 在 09:00 就已知；`get_price(frequency='1d', end_date=当前时间)` 在 09:00 返回**当天完整 OHLC**（含收盘），这是聚宽日频模式的未来数据陷阱，兼容层必须原样复刻并标注。
- `high_limit` / `low_limit` 由昨收和板块规则计算，09:00 即可用。

**对兼容层的影响**：日频回测的成交价不是开盘/收盘，而是**下单时点的盘中价**。要精确复刻 09:31、14:50 的成交，必须有分钟/5m 价格；只用日线 open/close 只能做近似。

**可行的精度分层**：

| 区间 | 精度 | 依据 |
|---|---|---|
| 2025-01-15 ~ 2026-10-30 | 精确 | 现有全市场 1m 数据可直接切片 |
| 2019 ~ 2025-01-14 | 近似或补 5m | 全市场 1m 约 96GB，不现实；5m 约 1/5 |

3. **点时财务数据**：`get_fundamentals(query, date)` 只能用 `pub_date <= date` 的记录。
4. **`get_current_data`**：`last_price`、`day_open`、`high_limit`、`low_limit`、`paused`、`is_st`、`name` 的取值以探针结果为准。

## 12. 盘中价格与复权口径实测（2026-10-31）

用 2025-07 之后有 1m 数据的真实成交，对照 `high_frequency/1min`：

| 策略 | 下单时点 | JQ 成交价 vs 1m 价格 |
|---|---|---|
| 成长多因子 | 09:30 | **完全相等**（8/8 笔等于该分钟 open） |
| 沪深300增强 | 10:00 | **完全相等**（4/4 笔等于该分钟 close） |
| 红利组合 | 13:30 | 差 1–2 个最小变动价位（10.68 vs 10.69） |
| 三正小市值 | 09:35 | 差 1–4 个最小变动价位 |
| 国证2000 | 11:30 | 差 1–2 个最小变动价位 |
| 自由现金流 | 14:50 | 差 2.5%（该策略未设 `use_real_price`，JQ 默认前复权） |

结论：

1. **09:30 与整点分钟的下单可以用 1m 数据精确复刻**；盘中其他时点受数据源差异影响，通常在 1–2 个最小变动价位内，验收时价格容差需放宽到 0.01–0.02。
2. **复权口径统一**：13 个策略中 12 个显式 `use_real_price=True`；自由现金流使用 JQ 默认前复权。策略组已决定把自由现金流也改为 `use_real_price=True`，因此**不实现前复权价格源**，全部策略统一走未复权撮合。注意：自由现金流的旧导出是前复权价，改为真实价后旧金标作废，需要重新回测并导出。
3. 精确窗口（2025-01-15 起）的建议验收：数量严格、价格容差 0.02、收益率容差 1e-3；策略层收益差异单独归因到数据源与盘中时点。

**实现进度**：

1. ✅ 1m 价格读取与缓存（`app/services/data/intraday.py`）；
2. ✅ 时点调度器（`timed_execution=true`，支持 09:00 / 09:30 / 09:31 / 09:35 / 10:00 / 11:30 / 13:30 / 14:30 / 14:50 / 14:55 / 15:10）；
3. ✅ 15:10 之后订单挂到次日 09:30；
4. ✅ 兼容层 T1/T2：`g`、`run_daily/weekly/monthly`、`get_price`（日线/指数/长表/涨跌停）、`get_current_data`、`get_all_securities`、`get_trade_days`、`get_security_info`、`get_fundamentals`、`get_factor_values`、`get_index_stocks`、`get_industry`、`finance.run_query`（分红）、下单/撤单/委托查询；
5. ✅ 事件引擎预热区间：聚宽策略首日可读上一交易日与历史窗口，权益曲线仍从回测起始日开始；

## 13. 2026-11-01 数据根因排查

### 13.1 已修复：聚宽净利润口径改为归母累计

数据事实（`free/financial_income`，`svquant-data` 已在契约里登记 `quarter_semantics`）：

- 累计：`revenue`、`total_operating_cost`、`tot_profit`、`net_profit_incl_min_int_inc`、`net_profit_incl_min_int_inc_after`；
- 单季：`net_profit_excl_min_int_inc`（归母）、`deducted_net_profit`（扣非）、`revenue_q` 等；
- `net_profit_incl_min_int_inc_after` 是**累计扣非归母**（列名里的 `incl_min_int` 有误导，2019Q1 万科为 11.28 亿而含少数净利是 32.06 亿）。

兼容层有两个错误：用**单季度** `deducted_net_profit` 除以**累计**净利润；以及 `inc_net_profit_year_on_year` 直接取 `pershare_index.inc_net_profit_rate`。现在两个字段都从利润表按归母口径派生：

- `adjusted_profit_to_profit` = 累计扣非归母 / 年内累加归母 × 100；
- `inc_net_profit_year_on_year` = (累计归母 − 去年同期累计归母) / |去年同期| × 100。

破净 2019-12-31 的候选池从 9 只变成 101 只（改前只有 601398 这类 34% 的公司被误筛）。

### 13.2 红利低波+红利成长在 2017 年选不出票的两个数据原因

- **A 池**：`roe_quality` 取当前年之前 3 个自然年的年末 ROE，2017 年需要 2014/2015/2016；财务数据自 2016-03-31 起，2014 与 2015 全空，`dropna()` 后为空 → A 池 0 只。
- **B 池**：`valuation.pe_ttm` 在 2017-01-16 之前全为空，2017-03 只有 110 只有值（TTM 需要 4 个季度财务）；`pe_ratio.between(5,50)` 过滤后为空 → B 池 0 只。

结论：2017 起步的红利用例被 2014–2015 财务历史阻塞（P1-7），不是引擎差异。2019 年以后 A/B 池能正常出票，对账区间可先用 2019 起。

### 13.3 破净首日选股的剩余差异

聚宽 2020-01-02 买入的 5 只里，600375/000635/600790 在**当前源码快照**的过滤条件下都不该入选：

| 标的 | `adjusted_profit_to_profit` | `inc_net_profit_year_on_year` |
|---|---|---|
| 600375.SH | -300.2 | -30.65 |
| 000635.SZ | 94.6 | -27.63 |
| 600790.SH | 94.8 | -16.57 |

即 `>80` 且 `>0` 的过滤会把它们全部排除。逐期核对过 2018Q3–2020Q3 的披露数据，没有任何一个报告期能让这三只同时满足条件。金标导出不含代码版本标识，最可能的解释是这份导出由过滤条件更松的早期代码产生。

在拿到带版本标识的金标之前，破净的 L1 差异只做记录、不追平。

### 13.4 三正小市值解锁

`svquant-data` 发布 `index_membership` 的 399317/399101/399303（2016-11-01 起）与对应指数日线。兼容层 `IndexMembership` / `IndexPriceStore` 增加派生视图回退：优先读 `<data>/index/index_weights|index_price`，缺失时读 `derived/index_membership`（按年分区长表，有行即成分，权重可为空）与 `derived/index_price`。

2019-01-02 首日 30 只持仓与聚宽重合 14 只，用例已可跑；全区间报告待产出。
