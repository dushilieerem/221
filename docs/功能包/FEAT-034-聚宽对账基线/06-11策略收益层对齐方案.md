# 11 个策略（最新版）收益层面对齐方案

> 2026-11-02。范围：11 个有「最新回测结果与代码修改」目录的公司策略；行业轮动两条线区间不同，本轮不做。

## 1. 背景

前一版对账用的是根目录导出的三件套，与「最新」目录的代码不是同一次回测，结论不能用（见 [04-13策略对齐路线](04-13策略对齐路线.md) 第 14 节）。策略组已确认：公司策略以「最新回测结果与代码修改」目录为准；最新版统一使用 `2016-09-30 ~ 2026-09-30`。

目前最新目录只有 `result_1.csv`（累计收益曲线），没有成交与持仓。因此本轮先做**收益层对账**，成交与持仓等策略组补 `transaction` / `position` / `log` 后再开。

## 2. 范围与目标

- 纳入 11 个策略：成长多因子、红利低波+红利成长、破净组合、三正小市值、自由现金流、回购小市值、国证2000、MA趋势跟踪、高斯趋势、沪深300增强、增速差额。
- 统一区间：**2016-09-30 ~ 2026-09-30，2428 个交易日**（已逐日核对，日期集合完全一致）。
- 本轮可比：**L0 参数与日历、L4 每日收益与累计收益、L5 收益指标**。
- 本轮不可比：L1 选股、L2 成交、L3 持仓。

目标一句话：**回答「最新策略在 ResearchEngine 里能不能复现聚宽的收益曲线」**，不对选股差异做归因。

## 3. 工具改造

1. 金标导入支持只有收益曲线的导出：读 `result_1.csv`（GBK，列为时间 / 基准收益 / 策略收益等），按累计收益还原每日收益，生成 `daily.csv`，不生成 `positions.csv` / `orders.csv`。
2. 用例可声明比对层级：`comparison.layers: [L0, L4, L5]`。加载器不再强制要求 `positions.csv`，比对只跑声明过的层。
3. 报告标题与结论区标注「收益层对账：无成交、无持仓」，避免被当成完整结论。
4. 旧的四份公司策略报告保留，但标注为不可用。

## 4. 用例规范

每个策略一个用例目录：

```text
tests/parity/cases/company_latest/<strategy_id>/
  case.yaml          # 最新代码、统一区间、基准、费率、比对层级
  jq_strategy.py     # 最新版源码快照（只读）
  expected/          # 本地金标（gitignore）
    daily.csv        # 由 result_1.csv 还原
    meta.json        # 导出时间、初始资金、来源文件
```

- 代码：一律取「最新回测结果与代码修改」目录里的文件，原样执行。
- 参数：基准取 `set_benchmark`；费率与滑点取 `set_order_cost` / `set_slippage`；`use_real_price` 全部为 True，走未复权撮合。
- 初始资金：收益层比对按比例计算，不影响 L4/L5；先用代码与导出推断值，等策略组确认后校正。
- 时点：07:02、09:01、09:30、09:40、14:55 等时点引擎已支持；`every_bar` 按 09:30 处理。

## 5. 分批执行

| 批次 | 策略 | 现状 | 预计耗时 |
|---|---|---|---|
| A 立即可跑 | 成长多因子、红利低波+红利成长、破净组合、三正小市值、自由现金流、沪深300增强、增速差额 | 数据与接口齐备；最新版里沪深300增强、增速差额都是聚宽代码，不再是 BigQuant | 每个 20–60 分钟，可并行 |
| B 需降级或补数据 | MA趋势跟踪、高斯趋势 | 策略按分钟回测编写，高斯直接读 1m；目前只有 2025 年后的分钟数据，2016–2024 只能日频近似 | 降级后 30–60 分钟 |
| C 阻塞 | 国证2000 | 依赖 `get_call_auction` 集合竞价五档，现有数据没有 | 需数据或策略组确认跳过 |

本轮实际能出收益结论的是 **A 组 7 个**；B 组 2 个出降级结论并标注；C 组 2 个先查数据。

## 6. 交付物

1. 11 个用例目录（代码快照 + case.yaml + 本地金标；金标不入库）。
2. 每个策略一份 L0/L4/L5 报告：累计收益差异、每日收益命中率、最大回撤与夏普等指标差异、首个收益分歧日期。
3. 一份汇总表：「能否复现收益曲线」一览，标注每个策略的数据不足段。
4. 工具改动走一个 PR。

## 7. 依赖

**策略组**

- `transaction` / `position` / `log`（补齐后开 L1–L3）。
- 每个策略的初始资金与基准，避免从曲线反推。

**数据组**

- 2011–2013 年报：2016-09-30 起点做 5 年回归需要。
- 399317 / 399101 在 2016-10 的成分（免费源从 2016-11-01 起）。
- 回购公告（`STK_CAPITAL_CHANGE` 口径）。
- 集合竞价五档、全市场 5m/1m：决定 C 组与 B 组能否正式对账。

## 8. 判读口径

- 只比收益时，差异只能说明「曲线不一致」，无法区分选股、成交、费用各自贡献；报告只给差异幅度与首个分歧日，不做归因。
- 2016–2018 段受财务历史与指数成分起点影响，预期偏差较大；报告标出「数据不足段」，不计入策略层结论。
- 收益曲线一致也不等于选股一致（可能互相抵消）。这一层只是第一道验证，三件套到位后再逐层拆。

## 9. 验收

1. 11 个用例都能 `validate`，金标日期与聚宽导出一致。
2. A 组 7 个至少各出一份 L0/L4/L5 报告，L0 全部通过；L4 给出首个收益分歧日与累计收益差。
3. 报告明确写清「本轮不含选股/成交/持仓」。
4. 全量测试保持全绿。

### 10.1 数据交付与解锁（2026-11-02 晚）

`svquant-data` 交付 research-rv-20261102-15 后，三个阻塞解除：

- 399317 / 399101 / 399303 成分与日线回填到 2016-09-30，三正小市值与自由现金流可以覆盖统一区间。
- 申万一级行业映射进入 `industry_daily.sw_l1_code`（如 600519 = 801120.SI 食品饮料），兼容层新增 `get_industry_stocks`，增速差额可运行。
- 2013–2015 资产负债表与现金流量表补齐季度行，沪深300增强的 TTM 现金流在 2016–2018 段可用。

新增已知偏差（写入报告）：

1. 申万映射是 latest_only，2016–2026 用当前分类，早期行业归属与当时可能不同。
2. 2013–2015 为 Eastmoney 当前历史值，`net_profit_incl_min_int_inc` 用归母近似。
3. 000015 历史成分 unresolved，红利用例基准按等价沪深300 处理。

兼容层同时修复：移除聚宽导入行时保留 `try` 块结构（`pass` 占位），避免 `try: from jqfactor import ...` 变成空块。

### 10.2 估值数据边界（2026-11-02）

`5_technical_derived/valuation` 的 `pe_ttm` / `ps_ttm` 目前从 2017-01-16 起才有值（`pb` 从 2016-04 起）。最新策略统一从 2016-09-30 开始，受影响：

- **增速差额**：股票池先用 `valuation.pe_ratio > 0` 过滤，2016-10 ~ 2017-01 池子为空；到 2017-01-16 只有 1 只有值，TTM 计算需要 11 个报告期，直接 KeyError 退出。本轮暂不纳入。
- **红利低波+红利成长**：B 池要求 `pe_ratio` 在 5–50，这一段只有 A 池出票。

已请数据组用 2013–2015 财务把 TTM 估值回补到 2016-09-30；回补后重跑这两个策略。
