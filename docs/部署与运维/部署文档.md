# ResearchEngine 部署文档

## 1. 部署架构

```text
WebApp / HTTP 客户端
        ↓ 内网 HTTP
ResearchEngine（一个服务进程 / 一个 Uvicorn Worker）
        ├── 外部只读 MarketData 发布目录
        ├── 本地配置、资产库与批量 SQLite
        └── 可选 OpenAI 兼容 AI 服务
```

仓库不提供 `install.sh`、Docker 镜像或自动部署流程；首次环境准备由部署人员执行。

---

## 2. 环境

| 环境 | 地址 | 用途 |
|---|---|---|
| dev | 部署人员配置 | 本地开发和功能验证 |
| test | 部署人员配置 | 集成/契约测试 |
| prod | 部署人员配置 | 当前按单实例服务运行 |

仓库不记录服务器地址或凭据。

---

## 3. 服务器要求

- OS：支持 Conda 和 Python 3.11 的 Linux 环境为当前运行基线。
- CPU、内存、磁盘：仓库未声明统一规格；按行情规模和回测负载评估。
- GPU：普通因子/策略回测不要求 GPU；具体 AI Provider 在外部运行。
- 磁盘：为 MarketData 挂载、批量 SQLite、日志、缓存和结果目录预留容量。

---

## 4. 软件依赖

- Conda。
- Python 3.11（`environment.yml`）。
- 项目依赖：`pip install -e ".[all]"`；如需本地开发测试可安装 `pip install -e ".[all,dev]"`。
- 可选 ClickHouse/AkShare 等组件只在启用相应 Provider 时需要。

---

## 5. 配置项

先复制模板：

```bash
cp config.example.yaml config.yaml
```

| 配置 | 用途 |
|---|---|
| `server.host` / `server.port` | 监听地址和端口，默认 `0.0.0.0:9527` |
| `runtime.max_workers` / `runtime.max_queue_size` | 回测并发及排队上限，默认 `2` / `8` |
| `data.dir` | 外部只读行情目录 |
| `data.manifest` | MarketData 清单，默认位于数据目录中 |
| `data.expected_version` | 可选的期望 `data_version` |
| `data.expected_manifest_sha256` | 可选的清单文件哈希 |
| `data.verify_hashes` | 是否校验清单中每个资产的 SHA-256 |
| `assets.*` | 因子数据库、工具、代码目录和策略索引路径 |
| `cache.*` | 缓存目录、TTL 和上限 |
| `storage.output_path` | 输出根目录 |
| `ai.base_url` / `ai.api_key` / `ai.model` | 帖子摘要兜底的 Provider URL、密钥和模型名 |

`config.yaml` 已加入 `.gitignore`。部署人员应在该文件中填写真实路径和 API Key，不要把密钥放进配置模板、日志、PR 或版本库。`ai.*` 目前只供 `/api/ai/post-summaries` 兜底使用。

### MarketData 配置

1. 将经过发布的 MarketData 目录以只读方式挂载或提供给服务用户。
2. 确认目录含 `data_manifest.yaml` 和其声明的资产文件。
3. 将 `data.dir` 指向该目录；如需锁定数据版本，再将 `data.expected_version` 设置为清单中的 `data_version`。
4. 可按需要启用逐文件哈希校验（`data.verify_hashes`）；发布切换前先核对清单和实际文件。

### 行情发布切换

服务在后台自动检测行情发布更新，**数据更新后不需要重启服务**：

1. 默认每 60 秒重算一次行情目录的 release 签名（只统计文件大小和修改时间，不读取数据内容）。
2. 签名变化且连续两次检查一致（说明文件写入已停止）后，按与启动期相同的清单校验装载新 release；切换前已开始运行的回测继续使用旧 release 跑完，新请求使用新 release。
3. 数据发布完成后约 1~2 分钟自动生效。`GET /api/data/status` 查看当前 `data_version` 和 `release_id`；需要在发布后立即生效时调用 `POST /api/data/reload` 手动重载。

注意：

- 设置了 `data.expected_version` 时，发布新版本必须同步更新 `config.yaml` 并重启服务，否则自动切换会因版本不匹配而保持旧 release；该配置留空（不锁定版本）时才能完全自动跟随发布。
- `data.verify_hashes: true` 会让每次重载执行全量 SHA-256；发布目录较大时会明显变慢，重载前需要留出时间。
- 详细契约见 [行情发布与重载 API](../功能包/FEAT-002-研究引擎/06-研究接口文档/data-release.md)。

## 6. 部署步骤

```bash
conda env create -f environment.yml
conda activate researchengine
python -m pip install -e ".[all]"
cp config.example.yaml config.yaml
# 手工编辑 config.yaml，填写行情路径、期望版本和 AI 配置
./scripts/research-engine.sh start
```

后台启动脚本会自动定位并激活 `researchengine` 环境。若 Conda 不在 `PATH`，可设置 `CONDA_EXE` 指向 Conda 可执行文件。

---

## 7. 启动顺序

```text
MarketData 发布/挂载就绪
        ↓
校验 config.yaml 和 data_manifest.yaml
        ↓
启动 ResearchEngine API
        ↓
调用健康检查
        ↓
开放给受控的 WebApp / 研究客户端
```

MarketData 发布需要先于 ResearchEngine 启动准备完成。AI Provider 不是普通 API 启动的强制依赖；调用 AI 接口时需要正确的网络、模型和密钥配置。

---

## 8. 健康检查

```bash
curl -fsS http://127.0.0.1:9527/api/health
./scripts/research-engine.sh status
```

服务默认监听 `0.0.0.0:9527`，健康检查应从本机或部署网络访问。生产访问控制需由受控网络或入口代理实施。

---

## 9. 日志与进程

- 默认日志：`logs/app.log`
- PID 文件：`run/app.pid`
- 查看日志：`./scripts/research-engine.sh logs`
- 只读一次日志：`./scripts/research-engine.sh logs --no-follow`
- 停止/重启：`./scripts/research-engine.sh stop` / `./scripts/research-engine.sh restart`
- PID、日志、配置、缓存及运行结果不应作为源代码提交。

---

## 10. 监控

仓库只提供健康端点和应用日志，不含 Prometheus、指标采集或告警配置。部署侧至少应监控：

- 进程存活与 `/api/health`。
- CPU、内存、磁盘和文件系统容量。
- 应用错误、任务队列满、回测失败和启动失败日志。
- MarketData 挂载状态、发布版本和批量 SQLite 增长。
- AI Provider 可用性和配额（若启用 AI 接口）。

---

## 11. 发布流程

```text
确认代码版本和依赖
        ↓
准备兼容的 MarketData release 与 config
        ↓
部署代码/资产
        ↓
启动或重启服务
        ↓
检查启动日志和 /api/health
        ↓
执行发布方指定的 API 冒烟验证
```

ResearchEngine 与调用它的 WebApp 当前按锁步方式发布；公开 HTTP 契约变化时应同步核对调用方。

该流程用于代码、配置和资产发布；单纯的 MarketData 日常数据更新不走此流程，服务会自动跟随发布切换（见[行情发布切换](#行情发布切换)）。

---

## 12. 回滚

仓库未实现自动回滚脚本。出现发布故障时，由运维人员恢复上一兼容代码/资产版本和对应数据 release 配置，再按启动步骤重启并检查健康状态。不要将旧 `data.expected_version` 与新数据目录混用。

---

## 13. 常见故障

| 问题 | 排查方式 |
|---|---|
| 缺少 `config.yaml` | 从 `config.example.yaml` 复制并检查 YAML 缩进 |
| 找不到 Conda | 将 `conda` 加入 `PATH` 或设置 `CONDA_EXE` |
| 找不到 `researchengine` 环境/Python | 检查 `environment.yml` 创建的环境和 Python 3.11 |
| 数据清单 SHA-256 不匹配 | 检查错误中 expected/actual、数据文件发布版本和清单；不要为绕过错误盲目改哈希 |
| 数据版本不匹配 | 核对 `data.expected_version` 与所挂载 Manifest 的 `data_version` |
| 数据已发布但服务仍读旧数据 | 用 `GET /api/data/status` 查看 `release_id` 是否已变化；确认自动切换未被锁定的 `data.expected_version` 拦住；需要立即生效时调用 `POST /api/data/reload` |
| 端口被占用或健康检查失败 | 查看 `server.port`、PID、`logs/app.log` 和进程状态 |
| 回测请求返回 `429` | 当前并发/排队容量已满；稍后重试或评估服务容量 |
| AI 请求失败 | 检查 `ai.base_url`、`ai.api_key`、`ai.model`、网络及对应环境变量覆盖 |
